# CrowdStrike Falcon Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: SOC-аналитик
или security engineer, впервые открывающий приложение, обычно в момент реагирования
на инцидент или настройки нового окружения.

## 1. Credential type
Falcon cloud region (`us-1` / `us-2` / `eu-1` / `us-gov-1`) + OAuth2 API Client
(Client ID + Client Secret), созданный в Falcon Console > Support and resources >
API Clients and Keys, со scoped-разрешениями на нужные коллекции (Hosts, Detections,
Incidents, IOCs, Prevention Policies, Real Time Response).

## 2. Идеальный флоу (без ограничений SDK)
1. **Явный выбор региона первым полем** — до ввода Client ID/Secret, так как регион
   определяет сам хост API и неверный выбор гарантированно ломает подключение;
   в идеале — с подсказкой "не знаете регион? посмотрите в адресной строке Falcon
   Console" прямо у поля.
2. **Чеклист нужных API scopes перед сохранением** — Falcon требует явного выбора
   scope на каждую коллекцию при создании API Client (Hosts: Read, Detections: Read/Write,
   Incidents: Read/Write, IOCs: Read/Write, Prevention Policies: Read/Write, RTR: Read/Write);
   идеально показать интерактивный чеклист "что нужно для каких функций" прямо в форме,
   чтобы пользователь не создавал Client с недостающими правами и не натыкался на 403
   только при первом реальном действии.
3. **Проверка подключения реальным вызовом перед сохранением** — запрос OAuth2 токена
   через `/oauth2/token`, затем один легковесный вызов (например
   `/devices/queries/devices/v1?limit=1`) чтобы подтвердить и валидность credentials,
   и что хотя бы Hosts:Read реально работает — а не просто сохранить пару ключей вслепую.
4. **После успеха — сразу estate health snapshot** — количество hosts, из них offline
   >7 дней, открытых detections/incidents по severity, и hosts с истёкшим/устаревшим
   sensor version, чтобы пользователь сразу увидел живые данные и понял, что подключение
   реально работает.
5. **401 vs 403 различаются явно** — 401 значит истёкший/неверный OAuth2 токен (нужно
   пересоздать Client Secret), 403 значит токен валиден, но конкретному Client не хватает
   scope на эту операцию (нужно добавить scope в Falcon Console) — это разные, конкретные
   причины ошибки, а не общий "unauthorized".
6. **Явное предупреждение перед network containment** — `contain_hosts` изолирует хост от
   сети (кроме трафика к Falcon cloud) — критичное действие, которое может прервать работу
   пользователя на этом хосте; идеально — двухшаговое подтверждение с явным текстом
   "хост будет отрезан от сети, кроме связи с Falcon" прямо в UI, не только в описании функции.
7. **Multi-tenant** — переключатель между несколькими подключёнными Falcon-тенантами
   (например, разные клиенты MSSP или dev/prod окружения), с явным лейблом
   "название (регион)" на каждом.
8. **RTR-сессии — явный индикатор "живая сессия открыта"** — Real Time Response даёт
   прямой доступ к хосту; идеально держать видимый статус активных RTR-сессий в сайдбаре,
   чтобы пользователь не забыл закрытую/незакрытую сессию.

## 3. Разница с реализацией сейчас
См. `UI_COMPONENT_PLAN.md` §0 — реализация ограничена наличными примитивами SDK
(`ui.Select` для выбора региона работает как обычное поле формы, но нет интерактивного
per-scope чеклиста — список нужных scopes описан текстом через `ui.Markdown` в help-диалоге,
а не как переключатели с live-подсказками). Containment/RTR-действия используют
стандартный `ui.Button` с `confirm=` (native SDK confirm-dialog), что покрывает идеал
разумно близко без отдельного кастомного экрана предупреждения.
